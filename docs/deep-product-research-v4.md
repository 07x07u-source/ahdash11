### Thmanyah font

- الموقع الرسمي يعلن ثلاث عائلات: `thmanyah Sans` و`thmanyah Serif Display` و`thmanyah Serif Text`، وخمسة أوزان لكل عائلة. Sans موصوفة كخط رقمي للشاشات، وSerif Display للعناوين. المصدر: [خط ثمانية الرسمي](https://font.thmanyah.com/).

- التنفيذ سيستخدم فقط الحزمة التي قدمها مالك المشروع، بعد التحقق من metadata الفعلية؛ لن يُحمّل خط من مصدر غير الحزمة ولن يُنشر في Admin أو endpoint عام.

### Game and responsive guidance

- Apple توصي بالدخول إلى اللعب سريعًا، defaults جيدة، التعليم عبر اللعب، وتأجيل طلبات الأذونات حتى سياق الحاجة. كما تشدد على النص المقروء، الأهداف اللمسية، safe areas، والتكيف مع 16:10 و19.5:9 و4:3. المصدر: [Apple — Designing for games](https://developer.apple.com/design/human-interface-guidelines/designing-for-games/).
- Apple تعتبر onboarding إن لزم سريعًا وممتعًا واختياريًا، مع tips سياقية بدل حشر كل التعليمات قبل الاستخدام. المصدر: [Apple — Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding/).

- `SafeArea` و`MediaQuery` هما الأساس لتجنب cutouts والحواف والنظام مع إمكان تمديد الخلفية full-bleed وحماية المحتوى فقط. المصدر: [Flutter — SafeArea & MediaQuery](https://docs.flutter.dev/ui/adaptive-responsive/safearea-mediaquery).

## Ahdash original product decisions

### Product hierarchy

- قلب المنتج: «تحدي أحدعش» — 6 فئات، 36 سؤالًا، فريق ضد فريق، مساعدات، Board، سؤال، كشف، نقاط، نتيجة.
- المنتج الرئيسي الثاني: «بطولة أحدعش» بخروج مغلوب V1، تعمل محليًا على جهاز واحد أولًا، وتستعمل Party Engine نفسها لكل مباراة.
- Home تعرض قرارين واضحين: «ابدأ لعبة» و«أنشئ بطولة»، ثم أفعالًا ثانوية صغيرة. لا grid قوائم ولا إحصاءات قبل اللعب.
- الحساب ليس حاجزًا للجولة المحلية الأولى؛ يصبح مطلوبًا عند sync وPremium والمفضلة السحابية والبطولات السحابية والأصدقاء.

### Tournament V1

- V1 = single elimination، مع 4/8/16/32/64 فريقًا واستخدام BYE لأي عدد غير قوة 2 من دون إسقاط فريق.
- 4 لاعبين افتراضيًا وقابلية ضبط 1–8 هي قاعدة أحدعش، مستلهمة من نمط البطولات العامة لا من واجهة منافس.
- Random draw وmanual seeds، bracket حتمي، winner advance بعد تأكيد النتيجة، tiebreaker يمنع تعادل مباراة خروج المغلوب، وundo فقط قبل بدء المباراة التابعة.
- التسجيل: إدخال يدوي أساسي؛ invite token آمن/رابط/QR عند تفعيل cloud. لا يلزم حساب لكل لاعب، ولا بيانات PII في الروستر العام.
- قواعد البطولة والفرق والفئات والمساعدات والمؤقت تؤخذ snapshot عند البدء ولا تتغير بتعديلات Admin اللاحقة.

### Visual system

- هوية أحدعش: charcoal + warm off-white + lime للحالة/CTA + gold للبطولة/Premium، مع هندسة ملعب وmotif 11 أصلية.
- لا نسخ لألوان Seen Jeem أو تكويناته أو رسومه أو مساعداته أو نصوصه أو حركاته.
- Login full-bleed بصورة أصلية/مولدة/مرخصة؛ fallback محلي فوري ثم slot بعيد `auth.login.background` مع scrim اتجاهي ثابت للقراءة.
- Profile شخصي وكروي، بإحصاءات inline وfavorite club accent آمن وشعار إجرائي عند غياب ترخيص.
- Tournament round-focused على الهاتف، لا spreadsheet ولا giant match cards؛ overview أفقي اختياري فقط.

### Monetization and rights

- يستمر RevenueCat الشهري/السنوي والاستعادة. لا coins ولا دفع لكل مباراة ولا pay-to-win.
- المجاني remote-configurable. Gifts/promo يبقيان architecture مستقبلية تتطلب التزام سياسات المتاجر وbackend authoritative.
- لا صور لاعبين أو شعارات أو أطقم أو بث أو تعليق أو كؤوس رسمية بلا حقوق موثقة. الفن المحلي سيكون أصليًا/مولدًا أو generic، والوسائط الخارجية تحمل rights metadata.

## Implementation guardrails

- لا تعديل لأي migration مطبقة، وبالأخص `20260830000100_party_game_content.sql`؛ أي schema جديدة تكون في migration جديدة فقط.
- لا تكرار لبيانات 6 دوريات/114 ناديًا، ولا إنشاء نظام Media Library موازٍ.
- لا `db push` فعلي. المسموح parser وPL/pgSQL validation وdb lint وRLS review وdry-run في النهاية.
- لا Emulator ولا تثبيت تلقائي. APK Release واحدة فقط بعد نجاح كل التحقق.
